# whisper-gigaam — локальный сервер транскрибации русской речи

Полностью локальный (офлайн) сервис распознавания речи на базе **GigaAM v3** — лучшей открытой модели для русского языка. Аудио никуда не отправляется: сервер и голосовой ввод работают на вашей машине.

Возможности:

- веб-интерфейс: запись с микрофона прямо в браузере (с выбором устройства) и транскрибация файлов любого размера;
- HTTP API для интеграций;
- пунктуация и нормализация текста в результате;
- голосовой ввод с горячих клавиш — речь превращается в текст и вставляется в активное окно (чат, редактор, мессенджер).

## Требования

- Windows 10/11 (x64); Linux тоже поддерживается для сервера;
- NVIDIA GPU с 6+ ГБ VRAM (CUDA 12.x) или CPU без GPU — оба варианта работают;
- [uv](https://docs.astral.sh/uv/) и [ffmpeg](https://ffmpeg.org/) — скрипты установки ставят их сами через `winget`.

## Быстрый старт

1. Запустите **start.ps1** (или двойным кликом по **start.bat** — это ASCII-обёртка над PowerShell-скриптом). Он сам установит `uv`/`ffmpeg`, соберёт зависимости и поднимет сервер.
2. Откройте **http://127.0.0.1:8010** — выберите микрофон в выпадающем списке, нажмите «Записать», говорите, затем «Остановить». Или загрузите аудиофайл и нажмите «Распознать».

Вверху страницы — переключатель **API-эндпоинта**: можно выполнить распознавание через старый `/transcribe` (родной формат с диагностикой) или новый `/v1/audio/transcriptions` (OpenAI-совместимый, verbose_json). Результат показывается с таймкодами сегментов и подписью, какой эндпоинт использован.

### Доступ с других устройств

Сервер слушает **все интерфейсы** (`HOST=0.0.0.0`): с других компьютеров и телефонов в той же сети откройте `http://<IP-этой-машины>:8010` (например, `http://192.168.130.155:8010`). Узнать IP: `ipconfig` → «IPv4-адрес».

- При первом запуске Windows может спросить разрешение межсетевого экрана — разрешите для частных сетей.
- Запись с микрофона из браузера на других устройствах потребует HTTPS (ограничение браузеров); API и загрузка файлов работают без ограничений.

> Первый запуск скачивает модель (~450 МБ) в папку `models/` один раз; дальше старт занимает секунды.

## Автозапуск (переживает перезагрузку)

Сервер можно поставить как службу Windows — будет запускаться автоматически при старте системы (до входа пользователя) и перезапускаться при сбое. Реализация — Планировщик заданий Windows (встроенная служба ОС, без сторонних утилит).

```powershell
.\service.ps1 install     # установить и запустить (показывает UAC-диалог — подтвердите)
.\service.ps1 status      # состояние задачи + здоровье сервера
.\service.ps1 stop        # остановить
.\service.ps1 start       # запустить
.\service.ps1 uninstall   # удалить службу
```

То же через двойной клик: [service.bat](service.bat) (`service.bat install` и т.д.).

- Задача называется **«WhisperGigaAM Server»** (Планировщик заданий → Библиотека планировщика).
- Работает от учётной записи **SYSTEM**: не требует входа в систему и пароля.
- При сбое — до 3 автоматических перезапусков с интервалом 1 минута.
- Логи: `logs\service.log` (ротация при превышении 10 МБ).
- Предварительно должен быть выполнен `start.ps1` (создание `.venv` с зависимостями).

## Настройки

Все параметры — в файле **`.env`** рядом с `pyproject.toml` (переменные окружения имеют приоритет над `.env`).

```ini
HOST=127.0.0.1              # адрес сервера
PORT=8010                   # порт
GIGAAM_MODEL=e2e_rnnt       # модель (см. таблицу ниже)
#GIGAAM_DEVICE=cuda         # cuda/cpu — по умолчанию выбирается автоматически
#GIGAAM_CACHE=D:\models     # папка кэша моделей (по умолчанию ./models)
```

### Модели

| Значение `GIGAAM_MODEL` | Описание |
|---|---|
| `e2e_rnnt` (по умолчанию) | GigaAM-v3 e2e RNNT — лучшее качество + пунктуация и нормализация |
| `e2e_ctc` | GigaAM-v3 e2e CTC — сопоставимо по качеству, быстрее |
| `rnnt` / `ctc` | GigaAM-v3 без e2e-головки — меньше памяти, текст без пунктуации |

Сменить модель: `.\start.ps1 -Model e2e_ctc` — или задайте `GIGAAM_MODEL` в `.env`.

### Откуда берутся веса

Веса моделей **не хранятся в репозитории** (`models/` в `.gitignore`). При первом
запуске сервера библиотека GigaAM сама скачивает нужную модель с официального CDN
Сбера (`https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM` — см. `_URL_DIR`
в пакете `gigaam/__init__.py`) в папку кэша:

- по умолчанию `./models/` внутри проекта (переменная `GIGAAM_CACHE`);
- для `e2e_rnnt` скачиваются два файла: `v3_e2e_rnnt.ckpt` (~448 МБ) и `v3_e2e_rnnt_tokenizer.model` (~250 КБ);
- доступны имена: `v3_ctc`, `v3_rnnt`, `v3_e2e_ctc`, `v3_e2e_rnnt`, `v3_ssl` (короткие имена `ctc`/`rnnt`/`e2e_ctc`/`e2e_rnnt`/`ssl` автоматически превращаются в `v3_*`).

Ручная установка (если нужен офлайн-перенос на машину без интернета):

```powershell
# скачает модель в указанную папку (имя как в GIGAAM_MODEL, можно v3_-префикс)
uv run python -c "import gigaam; gigaam.load_model('e2e_rnnt', download_root='D:/models')"
```

Требуется интернет только при первом скачивании; после этого сервер работает полностью офлайн.

## Голосовой ввод

Утилита `whisper_gigaam.voice`: микрофон → сервер → текст в активное окно.

1. Сервер должен быть запущен (`start.ps1`).
2. Запустите **start_voice.ps1** в отдельном окне.
3. Кликните в поле ввода (чат DeepSeek Harness или любое приложение).
4. **Ctrl+Alt+Z** — начать запись, снова **Ctrl+Alt+Z** — остановить. Текст распознаётся и вставится.
5. **Enter** — отправить.

### Выбор микрофона

```powershell
.\start_voice.ps1 --list-devices        # список доступных устройств
```

Укажите устройство в `.env` — фрагмент имени (без учёта регистра) или индекс:

```ini
VOICE_DEVICE=USB Condenser
```

Разово, без правки `.env`: `.\start_voice.ps1 --device "JBL"`. Если выбранное устройство недоступно (вынули USB-микрофон), программа автоматически перебирает остальные входы.

Прочие настройки голоса:

```ini
VOICE_HOTKEY=<ctrl>+<alt>+z   # комбинация старт/стоп (синтаксис pynput)
VOICE_PASTE=1                 # 0 — только буфер обмена, без авто-вставки
VOICE_SEND_ENTER=0            # 1 — сразу нажимать Enter после вставки
#TRANSCRIBE_URL=http://127.0.0.1:8010/transcribe   # если сервер на другой машине
```

Проверка без микрофона: `.\start_voice.ps1 --file запись.wav --print-only`.

## Портативный клиент (для удалённых машин)

Папка **[portable/](portable/)** — самодостаточный голосовой клиент для машин, где не нужен сервер: микрофон → ваш сервер по сети → текст в активное окно. Всего две зависимости (`sounddevice`, `pynput`), torch/GigaAM не требуются. Поддерживает оба API (`native` и `openai`).

1. Скопируйте `portable/` (или `dist/whisper-gigaam-voice-client.zip`) на удалённую машину.
2. Запустите **start_client.bat** — при первом запуске создаётся `.venv`, ставятся зависимости, открывается `client.env` для адреса сервера.
3. Ctrl+Alt+Z — говорите, снова Ctrl+Alt+Z — текст вставляется.

Подробнее — в [portable/README.md](portable/README.md). Проверка связи: `curl http://<IP-сервера>:8010/health`.

## HTTP API

### OpenAI-совместимый: `POST /v1/audio/transcriptions`

Полная совместимость с OpenAI Audio API — работает любой клиент/SDK, указав `base_url` этого сервера:

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8010/v1", api_key="local")

with open("record.mp3", "rb") as f:
    transcript = client.audio.transcriptions.create(model="whisper-1", file=f)
print(transcript.text)
```

```powershell
curl.exe -X POST http://127.0.0.1:8010/v1/audio/transcriptions -F "file=@record.mp3" -F "model=whisper-1"
```

Поля запроса: `file*`, `model*`, `response_format` (`json` | `text` | `srt` | `vtt` | `verbose_json`), `timestamp_granularities[]` (`word` | `segment`), `language`, `prompt`, `temperature`. Поля `language`/`prompt`/`temperature` принимаются, но игнорируются (модель русскоязычная, декодирование жадное).

Форматы ответа:

| `response_format` | Ответ |
|---|---|
| `json` (по умолчанию) | `{"text": "..."}` |
| `text` | обычный текст |
| `srt` / `vtt` | субтитры с таймкодами |
| `verbose_json` | `{task, language, duration, text, segments[], words[], usage}` — слова и сегменты по `timestamp_granularities[]` |

Ошибки — в формате OpenAI: `{"error": {"message", "type", "param", "code"}}`.
`GET /v1/models` — список моделей в формате OpenAI.

### Родной: `POST /transcribe`

Расширенный формат с диагностикой (используется веб-страницей и голосовым клиентом):

```powershell
curl.exe -X POST http://127.0.0.1:8010/transcribe -F "file=@record.mp3"
```

Ответ:

```json
{
  "ok": true,
  "model": "e2e_rnnt",
  "device": "cuda",
  "gpu": "NVIDIA GeForce GTX 1080 Ti",
  "audio_sec": 11.29,
  "processing_sec": 1.76,
  "text": "полный текст",
  "segments": [{ "start": 0.0, "end": 11.29, "text": "..." }]
}
```

**GET `/health`** — статус модели и устройства.

## Как это работает

- Запись в браузере идёт через MediaRecorder (webm/opus); файл любого формата декодируется ffmpeg в PCM 16 кГц моно (требование GigaAM);
- длинное аудио режется на куски ≤20 с по паузам — лимит `transcribe()` в GigaAM 25 с;
- каждый кусок распознаётся, результат склеивается с таймкодами сегментов;
- инференс сериализуется блокировкой — при параллельных запросах очередь, а не гонка в VRAM.

## Ограничения

- **Размер файла** — по умолчанию до **2 ГБ** (`MAX_UPLOAD_MB` в `.env`); при превышении ответ `413`. Проверка идёт по Content-Length до чтения тела.
- **Длина записи** — не ограничена: длинное аудио режется на куски ≤20 с и обрабатывается последовательно. Ориентир: 130 с аудио ≈ 7.5 с обработки на GTX 1080 Ti (**~17× быстрее реального времени**), часовая запись ≈ 3.5 мин ожидания.
- **Запись с микрофона в браузере** — MediaRecorder пишет в память вкладки; практически безопасно до ~1 часа записи (лимит RAM браузера, не сервера). На `http://127.0.0.1` работает без HTTPS; при доступе с других машин браузер потребует HTTPS.
- **Память сервера** — файл декодируется в PCM 16 кГц целиком (1 час аудио ≈ 110 МБ RAM).
- Разбиение по тишине — эвристическое (RMS-порог), границы сегментов приблизительные. Официальный longform через `pyannote` требует Hugging Face-токена и доступа к моделям pyannote — здесь сознательно не используется.
- `word_timestamps` (тайминги слов) в GigaAM поддерживаются и доступны через `/v1/audio/transcriptions` (`timestamp_granularities[]=word`).
- Порог тишины (`SILENCE_RMS`) может потребовать подстройки для очень тихих/шумных записей.

## Устранение проблем

| Симптом | Решение |
|---|---|
| Не найден `uv` | `winget install --id astral-sh.uv`, затем новая консоль |
| Не найден `ffmpeg` | `winget install --id Gyan.FFmpeg`, затем новая консоль |
| `No module named torch` | `uv sync` в папке проекта |
| `/health` показывает `device: cpu` | проверьте `nvidia-smi` и драйвер CUDA |
| `no kernel image available` | сборка torch не подходит GPU — см. `[tool.uv.index]` в `pyproject.toml`, выберите `cu121`/`cu128` |
| Вставка не появляется в окне | вывод voice-скрипта печатает активное окно и статус SendInput; elevated-окна требуют запуска от администратора |
| Микрофон не открывается | `--list-devices`, укажите другой `VOICE_DEVICE` |
| «Ничего не распознано» при живой записи | проверьте уровень микрофона в Windows (Параметры → Звук → Ввод) и что выбран тот самый endpoint устройства (`--list-devices`) |
| Сервер не стартует после клонирования | веса не входят в репозиторий — они скачаются при первом запуске в `models/`; нужен интернет (см. «Откуда берутся веса») |

## Диагностика голосового клиента

Клиент пишет только в консоль (отдельного журнала нет). Если текст не вставляется или
распознавание не запускается:

- в выводе клиента печатаются активное окно и статус SendInput при каждой вставке;
- полный цикл без хоткея проверяется так: `.\start_voice.ps1 --file example.wav --print-only`
  (нужен любой wav; положительный ответ означает, что микрофон ни при чём);
- связка «клиент → сервер» проверяется `curl.exe http://127.0.0.1:8010/health`.
